# DeepSeek V4 Pro: complete AITER fused MoE call

This task optimizes the complete upstream AITER fused MoE call at one selected site. Two authentic call cases, their measured frequencies, four input states and the numerical/timing policy define the task. Its protected input and runtime bindings are checked independently of the editable implementation.

The workload is DeepSeek V4 Pro, TP8/EP1/DP1, 64 ShareGPT-derived requests, concurrency64, input8192/output1024. Requests use the stock sampler's token-ID mode to preserve the selected 8,192 input IDs; decoding them to text and retokenizing can change the actual input length. Both methods and the fresh baseline use this same request policy. The protected workload file identifies the selected model revision, dataset and request policy. Inputs come from the reproduced workload; frequencies come from its separate complete accounting run.

The selected site is rank 0, `model.layers.3.mlp`, the first layer using learned expert selection in this model configuration. Hidden width is 7168, intermediate width is 384 per expert, and there are 384 experts with top-k 6. The supplied expert weights use the actual FP4/E8M0 representation. The task covers this site, with no extrapolation to other ranks or layers.

| Case | Tokens | Timing | Measured calls |
|---|---:|---|---:|
| `prefill_m8192` | 8192 | GPU events | 64 |
| `decode_m64` | 64 | CUDA graph | 1024 |

The score is upstream weighted time divided by candidate weighted time: each total is `64 * prefill_ms + 1024 * decode_ms`. The second authentic state of each case supplies correctness coverage and has no additional scoring weight. Repeated warm-input isolated-call timing is a search proxy; actual serving cache residency and end-to-end benefit are unmeasured.

## Operation and implementation freedom

The input boundary is the public `aiter.fused_moe.fused_moe` call: hidden states, already-selected expert IDs/weights, prepared expert weights/scales and explicit caller arguments. The output is the complete local routed-expert result. The operation includes its internal sorting, activation quantization, both projection stages, activation and output accumulation as selected by upstream dispatch. External expert selection and the subsequent TP collective are outside this boundary. The captured caller supplies BF16 hidden states with `a1_scale=None` and `a2_scale=None`; activation quantization is included in this public call.

`source/kernel.py` initially delegates the whole public call to the installed pinned upstream AITER implementation. The full upstream repository is acquired at an immutable revision under `upstream/` as protected source context. The optimizing agent may replace the delegation and add implementation helpers anywhere under `source/`, using the GPU backends available in the bound runtime. It may reorganize the complete computation; internal launches, layouts and intermediate buffers are not fixed targets. For this first task, externally supplied weights retain the serving loader's fixed preshuffle. There is no candidate load-time weight-transform step; candidate-specific conversions must execute inside the measured call.

Preserve the public function signature and returned tensor semantics. Inputs are read-only. New per-invocation preparation, conversions and intermediate work belong inside the timed call. Do not compute outputs or reusable input-dependent intermediates while importing the implementation. Static compilation is allowed. Do not alter the installed AITER package, protected upstream source, case data, reference, numerical policy, timing helper or evaluation scripts. Helper imports must remain within the allowed implementation/dependency boundary.

Each invocation must compute from its current dynamic inputs. Do not reuse dynamic-input-dependent results or intermediates from previous invocations, warmup or graph capture. Charging candidate weight transformations per call is an explicit limitation of this task, applied equally to both search methods. A task with separately charged static preparation would be a different contract.

The baseline is separately provided by the installed pinned AITER public call. The numerical reference calls the protected installed upstream PyTorch stages with independently frozen quantization/rounding choices. It never imports editable candidate code. Both roles use the same public inputs, correctness contract and complete-call timing policy.

## Existing Arena interface

All seven standard actions are implemented in `scripts/evaluate.py`:

```text
python3 scripts/evaluate.py validate-task
python3 scripts/evaluate.py baseline compile
python3 scripts/evaluate.py baseline correctness
python3 scripts/evaluate.py baseline performance
python3 scripts/evaluate.py candidate compile
python3 scripts/evaluate.py candidate correctness
python3 scripts/evaluate.py candidate performance
```

Each emits one `ARENA_EVAL_RESULT=` JSON envelope and exits nonzero on failure. Compilation syntax-checks the candidate module and exercises the actual callable/JIT path for the bound cases. Performance uses Arena's canonical `_aka_benchmark.py`, materialized by the normal workspace setup; no copied timing implementation is maintained here. Each case explicitly selects eager GPU-event timing (`cuda_event_fallback`) or graph timing (`cuda_graph`) through its protected `params.benchmark_method`. This permits source-supported prefill/eager and decode/graph regimes without assuming their case coverage. The returned timing method must match the declaration. The harness checks the actual measured outputs and their replay against the oracle. Each distinct public input backing storage is snapshotted once per input state and checked afterward, outside measured intervals. This includes bytes outside a sliced view, storage association/offset/size, tensor metadata and the public weight layout attributes.

Agent/model choices belong to the Arena run configuration. This package uses backend-neutral `candidate.language: gpu`; a native run through any particular agent adapter requires that adapter's independent qualification.

## Input and runtime contract

The scoring runtime binds the four extensions loaded by the baseline (core, Opus MoE, Opus sorting and quantization), the opaque FlyDSL stage-1 cache, and the complete upstream default MoE table-source set. Native identity is checked after the actual baseline calls. Cache identity establishes bytes, not which GPU instructions executed; the retained FlyDSL object contains compiled IR/launch metadata and is not a standalone HSACO. Build and input records remain separate from framework validation results. The large captured tensor carriers and native cache are external read-only runtime assets, not files distributed in this Git repository.

The task refuses scoring until its input and runtime binding is frozen. The protected records define:

1. **Runtime.** Set `runtime_binding.image_ref` to the composed scoring image's immutable Docker-inspected image ID (`sha256:...`), as supplied by Arena in `AKA_SCORING_IMAGE_RUNTIME_REF`, with `runtime_binding.build_evidence: {path, sha256}` pointing to a protected task-relative source/build/dispatch record. The build recipe may separately record a registry manifest digest. Bind every name in `scripts/runtime.py:DISPATCH_ENVIRONMENT` under `runtime_binding.dispatch_environment`, using the captured startup value before the first AITER import, or JSON null for absence. AITER itself initializes some variables during import, so a later environment dump is not interchangeable. The runner checks the effective environment before importing AITER; it does not silently replace inherited settings. This includes the selected `AITER_BF16_FP8_MOE_BOUND=0`, MoE dispatch switches and native source/cache roots. A nonempty `AITER_CONFIG_FMOE` override is unsupported until a protected table-content binding is added. The runner also requires exact runtime image ID agreement, the declared build-record hash, selected installed AITER source hashes, and gfx950. These checks supplement native qualification: the build record must join the effective native artifact to its source/build, and the checks alone do not prove that join. Setup performs no package installation or unlisted download.
2. **Inputs.** Add fresh workload-derived case records with `test_case_id`, `checks`, `shape`, `dtype`, `params` and `inputs`. The public shape is `[tokens, hidden_width, local_intermediate_width, experts, topk]`; dtype is `bfloat16`. `params.tensors` must list every public tensor's exact `shape`, `stride`, Torch dtype string, `storage_offset` in tensor elements, `storage_nbytes` and `storage_group`. Storage groups are capture-local nonnegative integer labels, shared exactly when tensors share backing storage; they are not pointer addresses. Capture these before copying or serializing inputs. The runner verifies loaded layouts, offsets, sizes and group equivalence across all public tensors, preventing a mislabeled or de-aliased case from being scored.
3. **Reference.** Freeze `numerical_contract` with the fields checked by `scripts/reference.py`. The adapter supports the upstream-test a8w4 staged reference structure. A1/A2 quantizers, clamping, gate layout and weight-application point require source/runtime evidence. Missing values fail; no tolerance defaults are supplied. Supported methods are explicit `allclose` and `aiter_checked_whole_call_v1`. The checked method fixes the upstream-default BF16 stage-1 reference, `rtol=atol=0.01`, and a combined rule: accept if every element is close or the FP64 normalized difference `D` is at most `0.001`. This uses upstream's tighter warning/check level as a rejection threshold, rather than its strict-test rejection threshold of `0.01`. It requires finite complete outputs/reductions and defines `D=0` for two all-zero tensors. The checked method was selected prospectively before baseline results and is declared in `numerical_contract`. Its global allowance can accept localized errors that elementwise allclose rejects; full-workload numerical validation remains necessary. Do not adjust the reference or thresholds to fit a baseline result.
4. **Frequency and timing.** Add a complete positive measured frequency map under `evaluation.aggregation` using `method: weighted_total_time`, with `source: {path, sha256}`. The IDs must exactly cover performance cases. The referenced JSON must declare `status: measured`, `enrolled_for_scoring: true`, and `case_counts` rows containing each `test_case_id` and positive integer `count` exactly matching the configured weights. Its `capture: {reference, sha256}` must identify a protected task-relative JSON receipt. That receipt's `exported_cases` must cover exactly the scored cases, with matching `test_case_id`, `shape`, `dtype`, `params`, `inputs` and `count`. The runner opens and hash-checks both records. This verifies the declared case/count/payload join; independent review must still establish that the receipt represents the actual workload and its declared coverage/aggregation. Input bytes are separately hash-checked when loaded. Every case must declare `params.benchmark_method` as `cuda_graph` or `cuda_event_fallback`; it is part of captured case identity. Freeze the shared `workloads.json.timing` fields `warmup`, `repetition`, `target_ms` and `max_graph_repeats`. There is no default timing method. Until those records exist, the runner rejects execution instead of using Arena's unweighted default.

The checked rule computes `D = 1 - 2 * sum(ref * out) / sum(ref² + out²)` after conversion to FP64. In exact arithmetic this equals `sum((ref - out)²) / sum(ref² + out²)`. It is not cosine distance: differing output magnitudes affect this expression even for parallel vectors. The explicit both-zero case and finite-reduction checks above remain part of acceptance.

`inputs` contains a task-relative `path`, SHA256, exact `call_kwargs`, `tensor_attributes` and a separate `weights: {path, sha256}` descriptor. Both files are tensor-only `torch.save` mappings loaded with `weights_only=True`. The case file contains only `hidden_states`, `topk_weight` and `topk_ids`. The weight file contains public `w1`, `w2`, `w1_scale`, `w2_scale` and protected oracle `canonical_w1`, `canonical_w2`, `canonical_w1_scale`, `canonical_w2_scale`; optional bias1/bias2 tensors belong there too. Multiple cases may reference one immutable weight file per rank/layer. The loader verifies both file hashes and checks that the canonical unshuffled weights/scales reproduce the public shuffled bytes. Canonical scales must have the unpadded shape `(experts * rows, logical_K / 32)`; public scale padding is not part of the oracle's logical K. Only public tensors are passed to the candidate.

Before splitting carriers, capture must establish that the public activation/routing storages do not alias any public weight/scale/bias storage and attest `inputs.input_weight_storages_disjoint: true`. Check this on the original serving tensors; separately loaded files cannot prove the original absence of aliases. Preserve complete backing storages and within-carrier view relationships through serialization. If cross-carrier aliases exist, this carrier is unsupported and must be extended before enrollment; cloning them away would change the workload contract.

Every case also binds `inputs.current_value_replay: {path, sha256}` to a second authentic activation/routing carrier in the same tensor-only format. The capture receipt must establish that both points have the same caller, rank, layer, prepared weights, complete tensor geometry, aliases and caller arguments. This additional point supplies correctness coverage and has no separate frequency or timing weight. Task validation compares the original oracle output with the second point's fresh oracle under the frozen numerical rule; if the original output passes, the pair does not establish stale-output rejection and a different authentic point must be bound.

Large activation and weight carriers may use the protected `runtime_binding.input_assets` mapping in `workloads.json`. Each key is the task-relative logical path used by a descriptor; its value declares a canonical container-visible absolute `path`, `sha256` and `size_bytes`. The operator mounts those files read-only outside the copied task, with no writable alias exposed to workers. The loader rejects local shadows, symlinks in the asset path, writable mounts, wrong sizes and digests that differ from the case. The same opened file is hashed before tensor loading. Missing assets fail without a download, environment-based lookup or implicit fallback. Every agent uses the same task runner and declared read-only files. Storage placement does not change the public tensors, workload frequencies or timing boundary.

After the original correctness or timing checks, the harness checks all original input storage before deliberately copying the second point's complete mutable backing buffers into the original public storage. It retains the public tensor objects, weights, offsets and aliases, snapshots the updated inputs, computes a fresh oracle, and checks the same callable again. For graph timing this uses `TimedRun.rerun()` on the exact graph that supplied the scored samples. The copy, oracle and extra execution are outside scored intervals. The updated full input backing storage must remain unchanged by the execution. Numerical tolerances and the declared timing policy apply equally to both roles.

Record the actual public weight attributes: `is_shuffled` must be the boolean `true`; `gate_up_interleave` may be absent, or must be the correct boolean (`true` for w1, `false` for w2) when present. The loader preserves recorded absence instead of inserting a marker, because AITER can use absence in dispatch. The interleaved preparation convention is separately established from the bound source/runtime and checked against the canonical bytes; it is not inferred from the optional attribute.

Before search, reference controls check the zero-hidden/no-bias path and reject a wholly incorrect output. The localized control follows the declared method: `allclose` rejects omission of a real output row with sufficient signal; `aiter_checked_whole_call_v1` rejects a single unit-valued element against a synthetic zero reference (`D=1`). A real row omission can lie inside the latter's global allowance and is not an unconditional rejection control. The checked method also reports a diagnostic that zeroes the smallest routing weight per token (first slot on ties), with stage-2 weighting, no renormalization, and every other input unchanged. It compares the resulting complete reference output using the same predicate and records the outcome without using that outcome as a qualification veto. These checks test comparator sensitivity within the fixed rule, not whether every routed expert has a measurable contribution. A native zero-input failure leaves the quantizer/reference path unresolved rather than proving that the reference implementation is wrong.

The first carrier covers one explicit local a8w4/interleaved family. Shared-expert arguments, EP masks, scatter destinations, caller-prequantized activations and output-destination variants require a corresponding input/reference extension when actual calls establish their relevance. Their current absence is a preparation limit, not evidence against those designs. The actual caller's block/dispatch overrides also require explicit binding before admitting a case; do not silently drop them.

Both captured cases have matching live and padded row counts: 8192 for prefill and 64 for decode. The adapter checks the complete returned tensor. Other padding buckets require their own workload binding; rows are not silently omitted.

Rank/layer coverage is limited to the selected rank-0, layer-3 call. No layer average or maximum across isolated ranks enters its score. Its weighted time is neither the simultaneous TP critical path nor an exact end-to-end latency.

Use all captured input states and complete workload cases prescribed by the frozen contract; this package does not invent a synthetic workload generator. The final comparison must remeasure upstream and candidate under the same cases and common complete-call timing. A local weighted-time improvement remains a proxy until integration and a complete same-workload E2E run confirm it.
