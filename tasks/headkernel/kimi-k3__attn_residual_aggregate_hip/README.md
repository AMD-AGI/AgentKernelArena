This package implements the current Kimi-K3 attention-residual aggregation task. It replaces the implementation tracked by the original `kimi-k3__score_combine_mix_fused` draft. The original logical head remains required; the new native capture is complete and GPU qualification is pending.

The active ROCm path is `AttnResidual` / `aggregate_stream` → `_aggregate_hip` → `attn_res_hip` → `_agg_kernel`. The kernel is Triton despite the upstream filename `attn_res_hip.py`. Its source is pinned to the exact SGLang 0.5.20 image. [source/attn_res_hip.py](source/attn_res_hip.py) exposes only `_agg_kernel` for edits; the wrapper, shape gate, imports, signature, launch controls and all other functions are protected. Candidate and frozen native reference load as separate private modules.

The native ABI includes a BF16 prefix, an optional residual addend, a snapshot bank, FP32 combined score weights, an optional output RMSNorm weight, the output buffer, and an optional materialized-prefix buffer. Hidden size is 7168 and the current bank has at most eight rows. A pending addition is rounded to BF16 before scoring; `write_prefix` copies that rounded prefix into the next bank row. Score and output epsilons are independent. All native aliases, strides, offsets and storage capacities are retained. The caller handles `nvb == 0` without invoking this aggregation kernel.

The independent mathematical oracle evaluates the score normalization, stable softmax mixture and optional output RMSNorm in FP32. It checks the complete output at the full native shape with 0.02 RMS-relative tolerance. Prefix and bank copies are exact. Complete input-storage snapshots detect changes outside the declared output/write intervals, including padding and untouched bank rows. Candidate observations are copied to CPU before any independent GPU reference runs; returned GPU reference storage is cleared afterward.

The capture adapter records the full native ABI and every actual workload occurrence. It retains the first four actual token rows per structural class as live source-parity evidence. This sampling is justified by one independent CTA per token with only matching-token bank and prefix accesses. Cross-token aliases are rejected because they invalidate that argument. The sample is explicitly **not a full native tensor dump**. Full-shape correctness is established independently on every fresh trial, and current captured token rows additionally validate candidate, frozen native source and mathematical-reference parity. Current score and norm weight vectors are retained in full.

Sampling keeps the capture within the existing budget: a full `[16384,8,7168]` BF16 bank alone is 1.75 GiB, while input/output bank copies and prefix buffers exceed the existing 2 GiB per-call snapshot limit. The token sample needs less than 2 MiB per case and does not change the model invocation, GPU work, tensor shapes used by the task, or occurrence counts.

[capture/SPEC.json](capture/SPEC.json) and [capture/adapter.py](capture/adapter.py) define the integration with a new supplemental served-hook bundle. The existing full-workload and graph notifications, all-rank coverage requirement, strict blob verification and finalization remain necessary. The old sampled profiler-window kernel counts do not substitute for new full-workload counts.

The finalized `kimi-original-heads-v2-194958` capture supplies all 69 exact cases: 23 each at 64, 8192 and 16384 tokens. All eight ranks recorded 196,602 calls each, totaling 1,572,816 actual aggregation calls. Each current case uses output RMSNorm; the complete observed residual-add and bank-write controls are retained. All cases include four actual token rows for native parity, with full-shape independent checks required. `provenance/CAPTURE.json` pins the final capture-ready, coverage and eight stop receipts.

The package uses the standard compile/correctness/performance entrypoints, 10 warmups, 100 checked single-call CUDA graph replays and mandatory no-op/wrong-output controls. Aliased outputs and post-input observations share one complete CPU storage snapshot, preserving every check while avoiding duplicate transfers of the same bank. Reference GPU outputs are erased before returning their owned CPU observations. Native GPU checks, submitted-source controls and a fresh framework-finalized validator PASS remain required before publication.
