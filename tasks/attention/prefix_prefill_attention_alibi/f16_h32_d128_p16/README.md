# Prefix-prefill attention with ALiBi, float16, 32 heads, head size 128, 16-token pages

Extend-step attention over a paged KV cache for ALiBi models (Bloom, MPT): `ctx_len` cached tokens
per sequence are read through a block table, `q_len` new tokens arrive dense. New token `i` sits at
position `ctx_len + i`; the score of key `j <= position` is
`sm_scale * q.k + slope[head] * (j - position)` and later keys are masked. Multi-head attention (one
KV head per query head), vLLM cache layouts (K: `[pages, heads, head_dim/x, page_size, x]` with
`x = 8`, V: `[pages, heads, head_dim, page_size]`), random physical page order, random finite data in
unused page slots.

**Production origin.** vLLM `_fwd_kernel_alibi` / `context_attention_fwd`
(`vllm/v1/attention/ops/prefix_prefill.py`). The slopes are the standard ALiBi geometric sequence
`2^(-8 (h + 1) / 32)` of 32-head Bloom/MPT models (head size 128), generated by `inputs.py`.

**Scenario and workloads.** `batch`, `q_len` and `ctx_len` vary, with identical lengths for all
sequences of a call (the launch grid derives the maximum query length from the packed token count).
Performance cases are chunked-prefill and prefix-cache shapes: 64-2048 new tokens over 2k-16k cached
tokens at batch 1-8 (more than 500x span of `batch * q_len * ctx_len`). Single-token and tiny extends
are correctness-only.

**Baseline.** vLLM's Triton `_fwd_kernel_alibi` (128x128 tiles for float16, `num_warps=4`,
`num_stages=1`) as simplified by the retired `triton_paged_prefix_prefill_alibi` task (fp8 cache
scales, input-precision and skip-decode parameters removed); the host wrapper became `run()`.
The old task's other shapes (head size 64, GQA/MQA) are not part of this scenario.

**Reference.** float64 attention with the bias added to the scaled scores, rebuilt from the paged
caches through the block table. Default comparison bound (`baseline_relative`).

**Numerics.** The slopes of the first heads (up to 0.84 per position) make the softmax almost
one-hot on the newest tokens, while the last heads (slope 2^-8) attend broadly; both regimes are
covered because all 32 heads are checked.

**Risks for the GPU audit.** The baseline computes `% block_size` and `// block_size` with a
runtime page size, which makes the context loop slower than the plain-attention kernel; the smallest
performance case (`1 x 64 x 2048`) is nevertheless expected above 10 us (unmeasured).
